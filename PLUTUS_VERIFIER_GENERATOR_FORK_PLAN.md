## EXECUTIVE SUMMARY

### The Problem

The Plutus verifier generated from the IOG `halo2_proofs` stub circuit expects a proof with **5 advice query evaluations**, but the actual midnight-zk circuit generates proofs with **30 advice query evaluations**. This causes on-chain verification to fail with:

```
Exception: PlutusTx.Builtins.Internal.error
```

### Root Cause

During VK deserialization, `VerifyingKey::read::<_, CircuitType>()` calls `CircuitType::configure()` to rebuild the constraint system. The IOG `halo2_proofs` stub circuit has **no chip configurations** (no gates), so it generates minimal queries (5), even though the VK was created from the full midnight-zk circuit with all chips configured (30 queries).

### The Solution

**Fork `plutus-halo2-verifier-gen` to use `midnight-proofs` types directly**, bypassing the need for a stub circuit. This ensures the Plutus verifier generator extracts the **actual constraint system** from the real midnight-zk circuit, generating a verifier that expects the correct proof format.

- ✅ **Single source of truth**: Real circuit = Plutus verifier circuit
- ✅ **Automatic synchronization**: Circuit changes → regenerate verifier
- ✅ **Highest security**: No manual gate translation, zero human error
- ✅ **Perfect generalization**: Works for any midnight-zk circuit (different RISC0 programs)

## PROBLEM STATEMENT

### Background

**midnight-groth16** is a RISC0 Groth16 verifier implemented as a Halo2 circuit using the **midnight-zk** library (PSE halo2 v0.3.0 fork). The goal is to deploy this verifier to Cardano via a Plutus smart contract generated by **plutus-halo2-verifier-gen**.

**The challenge**: `plutus-halo2-verifier-gen` expects circuits implemented with **IOG's `halo2_proofs`** library, but our circuit uses **midnight-zk's `midnight-proofs`** library. While both are PSE halo2 v0.3.0 forks, Rust's type system treats them as incompatible.

This is why we created this fork of the `plutus-halo2-verifier-gen` we call it the `plutus-midnight-verifier-gen`. 

Original code of the `plutus-halo2-verifier-gen` is also available here `~/iog_dev/plutus-halo2-verifier-gen` so we can take a look when we change this repository to support midnight-proofs. 

The midnight-zk implementation can be found here: `~/iog_dev/midnight-zk`

These original repositories are our source of truth when it comes to code and implementations.

## ROOT CAUSE ANALYSIS

### Query Generation in Halo2

In Halo2, **queries** are generated when gates reference columns at specific rotations:

```rust
meta.create_gate("example_gate", |meta| {
    let a_cur = meta.query_advice(column_a, Rotation::cur());   // Creates query 1
    let a_next = meta.query_advice(column_a, Rotation::next()); // Creates query 2
    let b_cur = meta.query_advice(column_b, Rotation::cur());   // Creates query 3
    vec![a_cur + a_next - b_cur]  // Constraint polynomial
});
```

This gate creates **3 queries**:
- `(column_a, Rotation::cur())`
- `(column_a, Rotation::next())`
- `(column_b, Rotation::cur())`

During proving, the prover evaluates the advice polynomials at the challenge point for each of these queries and writes the evaluations to the proof. The verifier reads these evaluations and uses them to check the constraint polynomial.

### How Chips Generate Queries

The real midnight-zk circuit uses three chips:

#### 1. NativeChip (15-20 queries)

**File**: `midnight-zk/circuits/src/field/native/native_chip.rs` (lines 161-257)

Creates **3 gates**:

**Gate 1: `arith_gate`** (lines 191-218)
```rust
meta.create_gate("arith_gate", |meta| {
    // Queries 5 value columns at current rotation
    let values: Vec<_> = value_columns.iter()
        .map(|col| meta.query_advice(*col, Rotation::cur()))
        .collect();

    // Queries 1 value column at next rotation
    let v0_next = meta.query_advice(value_columns[0], Rotation::next());

    // Queries 5 coefficient fixed columns
    let coeffs: Vec<_> = coeff_columns.iter()
        .map(|col| meta.query_fixed(*col, Rotation::cur()))
        .collect();

    // Queries 4 additional fixed columns (q_next, mul_ab, mul_ac, constant)
    let q_next = meta.query_fixed(q_next_col, Rotation::cur());
    // ... etc

    // Constraint: Σ(coeff[i] * value[i]) + q_next*v0_next + ... = 0
});
```

**Generates**: 5 advice (cur) + 1 advice (next) + 9 fixed (cur) = **15 queries**

**Gate 2: `12_minus_34`** (lines 220-227)
```rust
meta.create_gate("12_minus_34", |meta| {
    let v1 = meta.query_advice(value_columns[1], Rotation::cur());
    let v2 = meta.query_advice(value_columns[2], Rotation::cur());
    let v3 = meta.query_advice(value_columns[3], Rotation::cur());
    let v4 = meta.query_advice(value_columns[4], Rotation::cur());

});
```

**Generates**: **4 queries**

**Gate 3: `parallel_add_gate`** (lines 229-241)
```rust
meta.create_gate("parallel_add_gate", |meta| {
    let mut constraints = vec![];
    for (val_col, const_col) in parallel_columns.iter() {
        let val_cur = meta.query_advice(*val_col, Rotation::cur());
        let val_next = meta.query_advice(*val_col, Rotation::next());
        let constant = meta.query_fixed(*const_col, Rotation::cur());
        constraints.push(val_next - val_cur - constant);

```

**Generates**: 3 columns × (1 advice cur + 1 advice next + 1 fixed) = **9 queries**

**NativeChip total: 15 + 4 + 9 = 28 queries**

#### 2. Pow2RangeChip (4-8 queries)

**File**: `midnight-zk/circuits/src/field/decomposition/pow2range.rs` (lines 182-213)

Creates **lookup tables**:

```rust
pub fn configure(meta: &mut ConstraintSystem<F>, columns: &[Column<Advice>]) -> Self {
    let q_pow2range = meta.complex_selector();
    let tag_col = meta.fixed_column();
    let t_tag = meta.lookup_table_column();
    let t_val = meta.lookup_table_column();

    for val_col in val_cols.iter() {
        meta.lookup("pow2range check", |meta| {
            let selector = meta.query_selector(q_pow2range);
            let tag = meta.query_fixed(tag_col, Rotation::cur());
            let val = meta.query_advice(*val_col, Rotation::cur());

            vec![
                (tag.clone(), t_tag),           // Lookup query 1
                (selector * val, t_val),        // Lookup query 2
            ]
        });
    }
}
```

**Generates**: 2 value columns × 2 lookup queries = **4-6 queries**

## INVESTIGATION HISTORY

### Attempt 1: Modify Proof Format (REJECTED)

**Hypothesis**: Extract only 33 evaluations from the 124-evaluation proof to match Plutus expectations.

**Finding**: This is fundamentally flawed. The 124 evaluations correspond to different polynomial queries than the 33 expected. We cannot arbitrarily subset them without knowing the query mapping.

**Conclusion**: The proof is correct. The verifier is wrong.

### Attempt 2: Cross-Library VK Conversion via Re-Serialization (FAILED)

**Hypothesis**: Load VK with midnight-proofs types (gets full constraint system), re-serialize, then deserialize with halo2_proofs types (preserves CS).

**Implementation** (crates/midnight-groth16-cli/src/plutus/bridge.rs, lines 44-128):

```rust
// Step 1: Load with midnight-proofs types
let midnight_vk: MidnightVK<midnight_curves::Fq, MidnightKZG<midnight_curves::Bls12>> =
    MidnightVK::read::<_, MidnightCircuit<midnight_curves::Fq>>(
        &mut Cursor::new(midnight_vk_bytes),
        SerdeFormat::RawBytes,
        (),
    )?;

// midnight_vk.cs().advice_queries().len() = 30 ✓

// Step 2: Re-serialize
let mut reserialized = Vec::new();
midnight_vk.write(&mut reserialized, SerdeFormat::RawBytes)?;

// Step 3: Deserialize with halo2_proofs types
let plutus_vk = PlutusVK::read::<_, PlutusCircuit<blstrs::Scalar>>(
    &mut Cursor::new(&reserialized),
    PlutusSerdeFormat::RawBytes,
)?;

// plutus_vk.cs().advice_queries().len() = 5 ✗ FAILED!
```

**Test Results** (2025-12-06):
```
[INFO] midnight-proofs CS: 30 advice queries, 19 fixed queries
[INFO] halo2_proofs CS: 5 advice queries, 0 fixed queries
```

**Root Cause**: `VerifyingKey::read::<_, CircuitType>()` does NOT just deserialize the constraint system from binary. It **calls `CircuitType::configure()`** to rebuild gates and queries. Since `PlutusCircuit<blstrs::Scalar>` has no chip configurations (no gates), the CS is reconstructed with minimal queries.

**Key Insight**: The circuit type parameter in `VerifyingKey::read()` is not just for type compatibility - it actively participates in constraint system reconstruction.

**Conclusion**: Re-serialization cannot preserve the constraint system across incompatible circuit types.

### Attempt 3: Manually Recreate Gates in Stub Configure() (NOT FEASIBLE)

**Hypothesis**: Hand-code the same gate constraints directly in the stub circuit's `configure()` without using chips.

**Blockers**:
1. **Abstraction mismatch**: Chips use high-level abstractions (`meta.create_gate()`, `meta.lookup()`) with internal state management
2. **Lookup table complexity**: Pow2RangeChip uses dynamic lookup tables generated during synthesis
3. **Foreign field arithmetic**: FieldChip implements complex polynomial constraints that are non-trivial to recreate
4. **Parameter dependencies**: Gates depend on generic parameters (limb counts, base sizes, moduli)
5. **Maintenance nightmare**: Every chip update requires manual gate reconstruction

**Security Risk**: Manual polynomial constraints could introduce soundness bugs.

**Conclusion**: Not feasible due to complexity and security concerns.

## SOLUTION ARCHITECTURE

### Approach: Fork plutus-halo2-verifier-gen to Use midnight-proofs Directly (what we want to do here in this codebase)

**Core Idea**: Instead of converting types between libraries, modify the verifier generator to **natively support midnight-proofs types**.

The `plutus-halo2-verifier-gen` extraction logic accesses the constraint system via:

```rust

/// Extract circuit structure from midnight-proofs VerifyingKey 
///
/// This is the midnight-proofs equivalent of extract_circuit() in extraction/mod.rs
pub fn extract_circuit_midnight(
    params: &ParamsKZG<MidnightBls12>,
    vk: &VerifyingKey<MidnightFq>,
    instances: &[&[&[MidnightFq]]],
) -> Result<CircuitRepresentation> {
    let cs = vk.cs();

    log::info!("Extracting circuit structure from midnight-proofs VK");
    log::info!("  ├─ Advice columns: {}", cs.num_advice_columns());
    log::info!("  ├─ Instance columns: {}", cs.num_instance_columns());
    log::info!("  ├─ Fixed columns: {}", cs.num_fixed_columns());
    log::info!("  ├─ Advice queries: {}", cs.advice_queries().len());
    log::info!("  ├─ Instance queries: {}", cs.instance_queries().len());
    log::info!("  ├─ Fixed queries: {}", cs.fixed_queries().len());
    log::info!("  ├─ Gates: {}", cs.gates().len());
    log::info!("  └─ Lookups: {}", cs.lookups().len());

    // Create circuit representation
    let mut circuit_description = CircuitRepresentation::new();

    // Extract advice queries
    circuit_description.advice_queries = cs
        .advice_queries()
        .iter()
        .enumerate()
        .map(|(idx, &(column, rotation))| Query {
            commitment: format!("a{}", column.index() + 1),
            evaluation: format!("adviceEval{}", idx + 1),
            point: decode_rotation(rotation),
        })
        .collect();

    // Extract fixed queries
    circuit_description.fixed_queries = cs
        .fixed_queries()
        .iter()
        .enumerate()
        .map(|(idx, &(column, rotation))| Query {
            commitment: format!("f{}", column.index() + 1),
            evaluation: format!("fixedEval{}", idx + 1),
            point: decode_rotation(rotation),
        })
        .collect();

    // Extract instance queries
    circuit_description.instance_queries = cs
        .instance_queries()
        .iter()
        .enumerate()
        .map(|(idx, &(column, rotation))| Query {
            commitment: format!("i{}", column.index() + 1),
            evaluation: format!("instanceEval{}", idx + 1),
            point: decode_rotation(rotation),
        })
        .collect();

    // Extract permutation structure
    circuit_description.permutation_columns = cs
        .permutation()
        .columns
        .iter()
        .map(|col| format!("{}_{}", col_type_str(col.column_type()), col.index()))
        .collect();

    // Extract gates (gate expressions are not needed for Plutus, just count)
    circuit_description.gates_count = cs.gates().len();

    // Extract lookups
    circuit_description.lookups_count = cs.lookups().len();

    // Extract instance values (public inputs)
    circuit_description.instances = instances
        .iter()
        .flat_map(|instance_col| {
            instance_col.iter().map(|val_slice| {
                val_slice.iter().map(|fq| field_to_string(*fq)).collect()
            })
        })
        .collect();

    // Set instantiation-specific data
    circuit_description.instantiation_data = InstantiationSpecificData {
        q_evaluations_count: cs.advice_queries().len()
            + cs.fixed_queries().len()
            + cs.instance_queries().len(),
        public_inputs_count: instances.iter()
            .flat_map(|col| col.iter())
            .map(|vals| vals.len())
            .sum(),
        // ... other metadata
    };

    Ok(circuit_description)
}

/// Decode rotation to Plutus rotation format
fn decode_rotation(rotation: Rotation) -> RotationDescription {
    match rotation.0 {
        0 => RotationDescription::Current,
        1 => RotationDescription::Next,
        -1 => RotationDescription::Previous,
        n if n == -(params.n() as i32) + 1 => RotationDescription::Last,
        n => RotationDescription::Custom(n),
    }
}

/// Convert column type to string
fn col_type_str(col_type: Any) -> &'static str {
    match col_type {
        Any::Advice(_) => "advice",
        Any::Fixed => "fixed",
        Any::Instance => "instance",
    }
}

/// Convert midnight Fq to decimal string for Plutus
fn field_to_string(fq: MidnightFq) -> String {
    use ff::PrimeField;

    // Convert to bytes (little-endian)
    let bytes = fq.to_repr();

    // Convert to big integer
    let mut value = num_bigint::BigUint::from_bytes_le(bytes.as_ref());

    value.to_string()
}

### D. Query Deduplication

Halo2 automatically deduplicates queries: If multiple gates reference the same `(column, rotation)` pair, it's counted once. This explains why:

- **Sum of chip queries**: 37-44 (NativeChip + Pow2RangeChip + FieldChip)
- **Actual advice queries**: 30 (after deduplication)

Example: If both `arith_gate` and `parallel_add_gate` query `advice[0]` at `Rotation::cur()`, it's counted once.

### E. VK Deserialization Deep Dive

impl<F: Field, C: CommitmentScheme> VerifyingKey<F, C> {
    pub fn read<R: Read, Circuit: plonk::Circuit<F>>(
        reader: &mut R,
        format: SerdeFormat,
        circuit_params: Circuit::Params,
    ) -> io::Result<Self> {
        // Read serialized data
        let fixed_commitments = read_commitments(reader)?;
        let permutation_vk = read_permutation_vk(reader)?;

        // CRITICAL: Reconstruct constraint system by calling Circuit::configure()
        let mut meta = ConstraintSystem::new();
        let config = Circuit::configure(&mut meta, circuit_params);
        let cs = meta.build();  // Gates/queries generated here!

        Ok(VerifyingKey {
            cs,  // Uses Circuit's gates, not what's in VK bytes
            fixed_commitments,
            permutation_vk,
        })
    }
}
```

**Key Insight**: The `Circuit` type parameter is NOT just for type checking - it's actively used to rebuild the constraint system via `configure()`. This is why the stub circuit (no gates) produces a VK with minimal queries.
